## Interpretation

- Configured process-wide JS heap limit (jsHeapLimitMB): 1100 MB.
- 4 concurrent authenticated connections each ran a $where JS allocating ~1 MB strings in a global array.
- The limit is enforced per JS scope using thread-local counters (jscustomallocator.cpp:83-85: malloc_bytes/mmap_bytes/max_bytes are thread_local); there is no aggregate global accounting.
- Measured mongod RSS growth: 4003 MB = 3.64x the configured global limit at K=4, bounded by the JS loop completion window (~60 s).
- Scaling is linear in K: K=50 connections would plausibly demand ~55 GB aggregate.
- Per-scope interrupts fired correctly for every worker (no memory-safety issue); the weakness is resource accounting only (CWE-770 / CWE-400, DoS).

Environment note: RSS sampling uses `ps -C mongod` — Linux only; outputs above were captured on the VM.
